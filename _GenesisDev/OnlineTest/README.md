# Eventide OnlineTest для GitHub Codespaces

Стенд запускает одновременно:

- `Content.Server` в Linux Codespace;
- `Content.Client` в виртуальном X-дисплее Linux;
- лёгкий оконный менеджер и noVNC, чтобы открыть экран игрового клиента в браузере по ссылке из вкладки **Ports**.

Это не веб-порт самого SS14-клиента: браузер показывает удалённый рабочий стол, внутри которого работает обычный `Content.Client`. Игровой UDP-порт не нужно публиковать — клиент и сервер работают в одном контейнере и соединяются локально.

## Запуск

Из корня репозитория:

```bash
bash _GenesisDev/OnlineTest/start.sh
```

Первый запуск установит системные графические пакеты, если их нет, проверит/инициализирует подмодуль RobustToolbox и последовательно соберёт сервер и клиент. Это может занять время.

После запуска открой **Ports** в VS Code/Codespaces и найди порт **6080**. Если он не появился автоматически, выбери **Add Port / Forward a Port** и введи `6080`. Открой пересланный URL; должна появиться страница noVNC с рабочим столом и окном `Content.Client`. Оставь видимость порта `Private`.

В игровом клиенте выбери **Direct Connect** и подключись к:

```text
127.0.0.1:1212
```

Адрес `127.0.0.1` здесь правильный, потому что клиент и сервер находятся в одном Codespace-контейнере. Не подключай внешний лаунчер к URL порта 6080: это только браузерный экран, а игровой протокол использует UDP.

## Тикрейт

При старте скрипт смотрит на лимиты памяти/CPU контейнера и выбирает консервативный `net.tickrate` в диапазоне 10–30. Значение задаётся при запуске сервера, а не меняется на лету. Чтобы вручную задать, например, 20:

```bash
SS14_TICKRATE=20 bash _GenesisDev/OnlineTest/start.sh
```

Допустимый ручной диапазон — `5`–`60`. Меньший тикрейт может снизить нагрузку на сервер, но сам по себе не ускоряет рендеринг клиента и не гарантирует запуск графики на любом Codespace.

Если нужно пропустить сборку повторно после уже собранного проекта:

```bash
SS14_SKIP_BUILD=1 bash _GenesisDev/OnlineTest/start.sh
```

Используй это только если `Content.Client` и `Content.Server` уже собраны для текущих исходников.

## Управление

```bash
bash _GenesisDev/OnlineTest/status.sh
bash _GenesisDev/OnlineTest/stop.sh
```

Логи лежат в `_GenesisDev/OnlineTest/.runtime/logs/`: `server.log`, `client.log`, `websockify.log` и логи вспомогательных процессов. Служебная папка исключена из Git.

## Ограничения

- Виртуальный дисплей использует программный рендеринг Mesa; графика может быть медленной или не поддерживаться конкретной версией движка в headless-среде.
- Codespaces не предназначен для постоянного игрового хостинга. При остановке/пересоздании Codespace процессы остановятся.
- Это тест для локального клиента внутри Codespace, а не публикация игрового сервера для других игроков.
- Если клиент не открылся, проверь `_GenesisDev/OnlineTest/.runtime/logs/client.log`. Если сервер завершился — `server.log`. Скрипт не меняет игровые исходники или основной `Resources/ConfigPresets/server_config.toml`.
